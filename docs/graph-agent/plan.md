# GraphAgent 启动与验收计划

| 项目     | 内容                                                       |
| -------- | ---------------------------------------------------------- |
| 状态     | 设计草案；完成信号不代表当前已完成                         |
| 范围     | 从底层身份与聊天逐步扩展到工具、记忆、互操作与管理功能     |
| 原则     | 先打通最短闭环，再增加能力；每个阶段都必须可运行、可验收   |

## 0. 前置共享依赖

模型、账号、provider、协议 route、codec 和推理执行属于共享 Core，不在本计划中重复实施。GraphAgent 开始真实模型调用前，共享平台至少需要提供：

- 稳定的 provider/account/model 目录和协议 route；
- 可取消的推理调用、规范流事件与用量事实；
- 凭据共享端口，GraphAgent 不打开 PolyQuota 数据库；
- fake 端口与黄金 fixture，支持无网络测试。

这些依赖不阻塞阶段 1 的模板、实例和聊天领域逻辑，但阶段 2.1 的真实模型循环需要至少一条获准 route。模型选择、预算和亲和属于 GraphAgent 策略层，在阶段 2.2 先做简化版本，阶段 3.3 再补全。

## 2. 阶段 1：核心逻辑打通，聊天可用

### 步骤 1.1 模板定义与实例创建

**目标**：完成 AgentTemplate 定义，可以创建持久化实例与临时实例。

**交付**：

- `AgentTemplateRevision` 的不可变结构：身份、技能契约、模型/工具/委托/记忆/排班策略；
- `AgentInstance` 结构、身份种子、持久/临时雇佣类型和生命周期状态；
- 模板发布、实例创建、释放、page-out 与只读审计记录；
- 用工请求与简单实例选择（sticky、least-loaded、create、queue）；
- fake 存储与时钟，验证模板更新不影响已有实例。

**退出条件**：

- 同一模板可以创建多个持久实例和临时实例，身份、模板修订和权限可追溯；
- 临时实例完成职责后可以生成交接摘要并释放，历史记录仍可查询；
- 模板不可原地修改，实例不能引用不存在的修订；
- 不包含模型调用、任务图或工具执行。

**关联文档**：[01_Agent 模板与实例](./01_agent-template-and-instance.md)。

### 步骤 1.2 私聊与群聊机制

**目标**：私聊可以一问一答，群聊回复模式可以正确运行。

**交付**：

- Conversation、ChatMessage、AgentInbox、SessionRoute 的最小持久结构；
- 内置聊天界面或测试客户端，支持私聊和群聊；
- `@` 与普通群消息的接收规则：未屏蔽 `@` 为 interrupt 正文，普通群消息为 queue 无正文通知；
- 员工可以 `conversation_read` 查看正文，或不回复；
- 群聊回复沿原会话/线程发送，不自动唤醒全群；
- 空闲群聊接话的最小版本：通知合并、轮选、pass、一次替补、冷却和预算占位。

**退出条件**：

- 私聊一问一答可以完成，消息和回复可归档、可重放；
- 群聊中 `@` 的员工收到正文并可以回复，其他成员只收到通知；
- Agent 可以查看或忽略通知，普通回复不产生新的自动激活批次；
- 同一消息重复投递不重复响应；
- 挂起/恢复/停止仍只保留应用管理入口，不作为聊天命令实现。

**关联文档**：[02_消息聊天](./02_conversation-and-messaging.md)。

## 3. 阶段 2：最小可用

### 步骤 2.1 基础 Agent Loop 与文件/终端工具

**目标**：参考现有客户端实现基础 Agent Loop，提供文件和终端两批基础工具。

**交付**：

- turn/step/call 分层、持久输入、安全边界和 checkpoint；
- 单 provider route 的真实模型调用，或稳定 fake 流；
- 提示组合的最小 recipe：宿主规则、身份、任务、工具 schema、对话历史和当前输入；
- 文件工具：列表、读取、搜索、写入、精确替换；
- 终端工具：直接 argv、受管 shell、stdio 读取、等待和取消；
- 工具调用配对、错误返回、截断结果归档与继续读取；
- 基础预算预留与结算，先不做复杂软限额和跨设备。

**退出条件**：

- 用户提出目标后，Agent 可以读取资料、调用文件和终端工具并提交结果；
- 工具参数不完整或截断时不执行，完整结果与 call ID 正确配对；
- 模型流中断、工具失败和重启不会重复执行已发生副作用；
- 工作目录、编码、shell 和进程取消行为在 Windows 样本上可验证；
- 不要求任务图、派发、记忆或拦截器。

**关联文档**：[03_Agent Loop、派发与任务执行](./03_agent-loop-dispatch-and-execution.md)、[04_工具调用](./04_tool-execution.md)、[tools/](./tools/README.md)。

### 步骤 2.2 简单派发与任意层级 subagent

**目标**：实现没有预算和任务亲和机制的简单 Agent 派发，并支持任意层级 subagent 派发。

**交付**：

- Goal、Task、TaskAttempt、Assignment 的最小结构；
- 协调 Agent 可以创建子 Task 并派发给其他实例；
- 接受、拒绝、排队的最小协议；
- 子 Agent 可以继续派发 subagent，层级不固定，但受最大深度和实例容量保护；
- 任务终态与交付物最小验收；
- 邮箱顺序处理邀请，长任务让出邮箱；
- 简单恢复：重启后待处理派单和运行中任务不丢失。

**退出条件**：

- 一个入口可以分成多个子任务并合流；
- 子 Agent 可以继续派发，层级深度可配置；
- 多来源同时派单不丢邀请、不混上下文；
- 取消父任务时，独占子工作可取消，共享工作只移除请求者；
- 预算只做占位或简单上限，不做完整预留、软限额和亲和；
- 不要求跨设备，所有实例在本机运行。

**关联文档**：[03_Agent Loop、派发与任务执行](./03_agent-loop-dispatch-and-execution.md)。

## 4. 阶段 3：强化

### 步骤 3.1 内置记忆

**目标**：实现内置记忆，使员工可以跨任务保留可检索知识。

**交付**：

- 原始消息档案与记忆库分离；
- 默认 Markdown 文件/真实目录后端，一份文件一条记忆；
- 短期、长期、journal 三类记忆和 `MEMORY.md`/`USER.md` 自动注入；
- `memory_list/search/read/manage` 与 `conversation_recall` 工具；
- 关键词、标签、目录和时间检索，索引可重建；
- 版本检查、归档、外部编辑冲突和来源引用。

**退出条件**：

- 不调用模型也能建立目录、编辑记忆并检索；
- 通用文件/终端工具不能绕过记忆工具修改宿主管理资源；
- 删除索引后可重建相同知识视图；
- 长期记忆按预算注入，实际采用版本可从调用快照回查；
- 原始消息不被压缩、recap 或记忆更新覆写。

**关联文档**：[05_拦截器、记忆、整理与技能](./05_interception-memory-and-skills.md)。

### 步骤 3.2 技能加载与生成

**目标**：实现 Skill 加载与生成，使程序性经验可版本化管理。

**交付**：

- `SKILL.md` 目录包、附件清单和完整包 revision；
- 技能草稿、启用、停用、合并和旧版本保护；
- 按任务与工具授权选择技能，只注入适用摘要、步骤和验证方式；
- recap 可以生成技能草稿；
- 技能依赖的工具缺失时明确不可用，不临时扩权。

**退出条件**：

- 运行中的 Loop 继续使用旧技能版本，合并/停用不破坏执行；
- 技能脚本存在不代表有执行授权；
- 外部导入技能默认不可信；
- 技能正文不提升为宿主规则。

**关联文档**：[05_拦截器、记忆、整理与技能](./05_interception-memory-and-skills.md)。

### 步骤 3.3 跨设备多客户端派发与完整策略

**目标**：实现跨设备多客户端派发，并补齐预算、模型选择和亲和机制。

**交付**：

- 控制面与执行面分离，多设备 Worker 注册、心跳、能力和容量；
- 设备位置、资源、trustZone、provider 和反亲和约束；
- 完整 Goal → Task → Assignment 预算树、原子预留、结算和软限额收尾；
- `ModelPolicy` 交集、共享模型目录过滤、`ProviderRouteSelection` 和 `ModelLease`；
- 跨模型/协议交接的可移植摘要和效果核对；
- 多客户端同时连接时的单写入者、epoch 和 fencing；
- 离线、重连、取消和未知效果处理。

**退出条件**：

- 同一 Workspace 的任务可以派发到不同设备，事实仍由单一 Ledger 管理；
- 并发子任务不能超售同一预算；
- 目录刷新或账号变化不影响在途流；
- 设备丢失不会自动在另一设备重做未知副作用；
- 未获准的 Worker 不能扩大权限或预算；
- 本机模式与跨设备模式使用相同领域契约。

**关联文档**：[03_Agent Loop、派发与任务执行](./03_agent-loop-dispatch-and-execution.md)、[共享 Provider Platform](../common/core/cross-provider-service-protocol-design.md)。

### 步骤 3.4 剩余工具

**目标**：补齐除文件、终端之外的工具能力。

**交付**：

- `files_prepare/apply`、实时搜索选择、逐项排除和版本化提交；
- `result_read`、文件 diff/patch/三方合并；
- Git 状态、差异、历史、暂存和提交；
- 网页 `web_search/web_extract/web_crawl`，首版优先 Tavily；
- `http_request/http_download`、后台下载与完成/失败事件；
- `media_view` 图片与默认 15 秒内短视频；
- `execute_code` 一次性 Node/Python；
- `ask_user`、`todo_read/todo_update`；
- Browser use 按需安装 Chrome DevTools MCP；桌面能力作为可选扩展。

**退出条件**：

- 每项工具按专项矩阵验证失败、取消、重启和部分失败；
- 大结果可继续读取，不重执行原操作；
- 文件修改返回逐项命中/改动和写后核验；
- 网页结果区分搜索摘要、抽取正文和抓取覆盖；
- 工具存在不代表已授权，远端声明能力默认待验证。

**关联文档**：[04_工具调用](./04_tool-execution.md)、[tools/](./tools/README.md)。

### 步骤 3.5 拦截器

**目标**：实现可配置的拦截器与策略门。

**交付**：

- 用户输入、派单、消息、上下文读取、模型请求/响应、工具调用/结果、产物发布和记忆写入拦截点；
- `continue/transform/block/require-input/short-circuit` 决策；
- 版本化 binding、处理器顺序、策略快照和审批绑定；
- 确定性安全处理器与受控语义审查员工；
- 变换后重新校验权限、资源和副作用；
- 流式内容的首版完整消息检查与发布。

**退出条件**：

- 秘密在输入、记忆、摘要、附件、工具错误和产物中均不能未授权外发；
- 参数或目标变化使旧审批失效；
- 语义审查不递归调用自身，也不能借 bypass 跳过本地检查；
- 拦截不能扩大权限或直接完成 Task；
- 用户暂停/停止不被拦截器或 Agent 绕过。

**关联文档**：[05_拦截器、记忆、整理与技能](./05_interception-memory-and-skills.md)。

## 5. 阶段 4：优化与额外功能

### 步骤 4.1 高级任务工作流

**目标**：实现群聊任务发布与接收、任务转包、临时会话、消息打断、任务图监控和其它高级任务工作流管理。

**交付**：

- 群聊中从讨论发起正式委托，生成 DelegationRequest/Task；
- 任务转包、责任链、授权交集和预算来源展示；
- 挂起并临时聊天、恢复和资源处理；
- interrupt/queue/steer 的接收目标与生效位置可视化；
- 分叉合流、返工轮次、共享消费者、独占后继和未知效果核对；
- 候选竞争、独立评审、批量并行尝试和跨 Goal 产物复用；
- 工作台中的完整任务图监控与干预入口。

**退出条件**：

- 群聊消息不会直接变成 Assignment；
- 转包不改变最终交付责任，除非用户明确转移；
- 临时会话不自动恢复原工作，原资源和工具结果正确配对；
- 高级工作流不破坏单一交付责任人、版本化输入和预算归因。

**关联文档**：[02_消息聊天](./02_conversation-and-messaging.md)、[03_Agent Loop、派发与任务执行](./03_agent-loop-dispatch-and-execution.md)、[06_工作台与外部对接](./06_workspace-and-integrations.md)。

### 步骤 4.2 定时任务、Recap、做梦与记忆整理

**目标**：实现定时任务、recap 自我优化、做梦和记忆整理。

**交付**：

- 定时任务配置、时区、目标 namespace、预算、权限快照和通知；
- 任务结算触发 recap，生成短期记忆与技能草稿；
- 手动/空闲/定时做梦，批量用途选择 dreamModel；
- `prepare → reflect(optional) → consolidate → validate → commit → report` 阶段；
- 候选来源门槛、证据复核、CAS、journal、冲突界面和回填；
- 索引维护、失败重试和变更集回滚。

**退出条件**：

- 短任务可以产生有证据的记忆/技能；
- 做梦使用独立上下文，不扮演原员工；
- 并发编辑不覆盖新内容，journal 不可原地改写；
- 合并/删除不破坏运行中的旧技能；
- 整理失败不改变任务终态；
- 无可用批量候选时按配置回退或明确排队。

**关联文档**：[05_拦截器、记忆、整理与技能](./05_interception-memory-and-skills.md)、[06_工作台与外部对接](./06_workspace-and-integrations.md)。

### 步骤 4.3 A2A 协议适配

**目标**：实现 A2A 导入与发布。

**交付**：

- `AgentDeployment` 和 AgentCard 确定性投影、签名与扩展声明；
- 外部任务 → 内部 StaffingRequest/Assignment 映射；
- 内部状态到 A2A TaskState 的粗粒度映射；
- Artifact 发布、`contextId` 连续性、实例亲和扩展；
- 外部 AgentCard 导入为受限 RemoteAgentTemplate；
- 远端任务 ID、cursor、Artifact、取消和未知消耗处理；
- 固定规范版本和 interop fixture。

**退出条件**：

- 未协商扩展的标准 A2A Client 仍可使用 AgentCard 和 Task API；
- Message 不作为正式结果唯一载体，结果形成 Artifact；
- 外部技能声明默认不可信；
- 取消请求被接受不等于远端已终止；
- 内部 PAUSED/WAITING/UNKNOWN 不伪装成 A2A 新枚举。

**关联文档**：[06_工作台与外部对接](./06_workspace-and-integrations.md)。

### 步骤 4.4 外部 Agent 与 Coding Agent 远程调用

**目标**：支持外部 Agent 和 Codex/Claude Code 等外部客户端的远程调用。

**交付**：

- 外部客户端接入 GraphAgent 的受控 API：提交任务、状态流、干预和产物读取；
- GraphAgent 调用外部 coding agent 的 `RemoteAgentPort` 适配器；
- 远端会话 ID、事件 cursor、取消、重连和未知效果处理；
- 工作区路径、工具、预算和凭据的显式授予；
- 产物在纳入本地验收前重新读取和核对；
- 厂商公开 CLI/SDK 或 MCP 适配，不复制其运行时。

**退出条件**：

- 外部客户端不能直接写 Ledger 或绕过用户管理命令；
- 外部 Agent 不能继承内部凭据、记忆库或拦截配置；
- 远端取消和未知结果可解释；
- 远端事件不重复，progress 不被当作本地终态；
- 适配器版本、授权和沙箱行为有固定 fixture。

**关联文档**：[06_工作台与外部对接](./06_workspace-and-integrations.md)。

### 步骤 4.5 管理看板

**目标**：实现跨领域的管理看板。

**交付**：

- 运行中 Goal、任务图规模、等待/失败/暂停和关键阻塞；
- 员工容量、排队、Drain、page-out 和实例健康；
- 预算消耗、预留、未知用量、账号窗口和后台整理费用；
- 拦截阻断、审批积压、未知效果和完整性冲突；
- 定时任务、recap/做梦作业、失败重试和变更集回滚入口；
- 外部连接健康与最近错误。

**退出条件**：

- 看板只读聚合投影，管理动作仍走领域应用服务；
- 数据与各领域权威快照一致，不引入第二套状态；
- 凭据和原始秘密不进入看板；
- 关键阻塞和失败原因可定位到对象与命令。

**关联文档**：[06_工作台与外部对接](./06_workspace-and-integrations.md)。

## 6. 验证层次

| 层次            | 主要证据                                                                           |
| --------------- | ---------------------------------------------------------------------------------- |
| 领域契约        | 图修改原子性、版本、生命周期、共享取消、循环与权限不变量                           |
| 运行恢复        | 关键提交点注入崩溃、重放、重复投递、旧 epoch、未知工具效果                         |
| 预算与策略      | 并发预留、用量未知/迟到、软限额收尾、辅助任务费用、安全失败                        |
| Provider/工具   | 无网络 fixture、完整工具配对、原生状态、取消与最小真实账号闭环                     |
| Agent Loop/提示 | turn 与任务终态分离、输入边界、截断/中断工具参数、用途能力、来源权威、实际调用快照 |
| 知识整理        | 树目录检索、revision 冲突、独立上下文、journal 不变性、技能版本保护                |
| UI/宿主         | fake 应用服务、图干预、多面板/断线、生命周期、真实宿主资源与打包行为               |
| 外部互操作      | A2A fixture、外部客户端重连/取消、未知远端效果、凭据隔离                           |

实现修改按仓库要求运行 `format`、`typecheck`、`test`、`build`；涉及 Electron/native/打包再运行 `package`。纯文档修改只检查文档格式、链接与设计一致性，不执行代码检查、测试或编译；这些验证不能证明运行完成信号。

## 7. 启动前需落实的决策

- 领域 schema 与状态表定稿，优先解决 Task/Assignment 的恢复和取消语义。
- Ledger/内容存储选择，以原子预算、outbox 与恢复实验为依据。
- 本机 Activity 与工具进程协议，明确子进程取消和效果核对能力。
- 共享凭据代理的宿主、传输与跨产品迁移验证。
- 首个真实推理 route、usage/费用来源及跨协议 fixture。
- Markdown MemoryStore 与 SQLite 原始消息档案的发布/恢复协议；工作/辅助模型组合。
- UI 框架、图布局和桌面/本机服务宿主，完成真实原型评估。
- 跨设备 Worker 注册、租约、fencing 与离线恢复协议。
- A2A 规范版本、外部 coding agent 适配器的固定版本与沙箱行为。

这些选择不阻塞当前功能设计；实施到对应阶段时，以可审查样本和完成信号确认，不把草案当作已选定工程结构。
