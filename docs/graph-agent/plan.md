## 1. 实施顺序

先确认领域契约和 fake 端口下的任务协作，再落地共享推理骨架，之后建立首条真实执行路径、可观察工作台和记忆整理。2.5D 办公室及人物互动不进入任何里程碑。

本轮交付为设计文档。`apps/graph-agent` 仍是占位；建立运行包、提取协议、迁移凭据和真实账号任务分别按对应里程碑实施。

## 2. G0：领域与可恢复协作样本

目的：证明 graph 语义可执行，避免 UI 与模型接入掩盖协作缺陷。

工作：固定 Goal/TaskRevision/Attempt/Assignment/Artifact schema；实现 fake 时钟、模型、工具、预算与存储，以及[08 Agent Loop](./08agent-loop.md)的输入、step、流结算与[10 提示词组合](./10prompt-composition.md)的版本快照；验证多来源派单、接受/拒绝/排队、分叉合流、有限循环、责任与取消规则；用恢复实验选择事务存储与本机运行结构。

完成信号：基础模型→工具→结果→下一步骤可贯通，输入重复/干预边界、提示版本与用途能力可验证；同一入口可执行两条分支再合流；同员工收到两个上游邀请不混工作；共享消费者取消不误停其余工作；要求修改、重复命令、旧 epoch 回报与重启都有确定结果；恢复事件不执行外部工具。

[09 会话设计](./09conversation-and-messaging.md)的样本同时覆盖私聊直达 subagent、群聊 `@`/全体的逐收件人投递、interrupt/queue/steer 互斥消费，以及挂起工作→资源继续运行→同一员工临时处理→明确恢复。验证挂起不主动通知父员工，迟到工具结果仍归原上下文，关闭聊天不自动恢复；不能留到 UI 阶段才发现会话模型不成立。

投递样本固定覆盖 `@` interrupt 正文、普通群消息 queue 无正文通知和 Agent 查看/忽略；未启动员工被未屏蔽 `@` 启动新会话，并发启动去重。群/私聊作业屏蔽包含 `@`，只有任务终态才统一 queue，验证暂停/交接/重启不提前释放，以及终态与新消息并发不丢失/重复通知。通知应用与正文读取由既有 Loop/工具日志区分，自动上下文不偷带正文；不要求先实现外部平台集成或独立通知/回执数据库。

这一阶段可以和共享平台 G1 并行开展，但使用 fake 共享端口，不另建 provider/protocol 基础类型。

新增会话验收：Agent 工具与平台 /pause、/resume、/stop 无法执行用户管理动作；已挂起员工不会被 @、自动群聊或配额恢复唤醒。空闲自动接话验证通知合并、单接话人/一次替补、冷却与小时预算、员工回复不自激活；全部 pass 或预算不足保持可见未接话状态，不无限重试。

## 3. G1：共享推理与凭据前置项

目的：使业务执行绑定真实共享平台，保持两个产品的凭据与协议边界。

工作：按共享设计阶段 E 固定 protocol route、model catalog、codec、ModelStreamEvent、PreparedProviderCall 与 lease；四类协议建立黄金 fixture，即使真实执行只选一类；固定可用模型/账号声明与费用事实。按凭据专项设计提供受控共享端口、单写入者与迁移验证。

完成信号：fake Executor 完成能力筛选、prepareCall、取消与工具循环契约；有损/不支持转换明确拒绝；跨客户端刷新有唯一写入者；GraphAgent 无需打开 PolyQuota 数据库。真实接入前核验目标账号同时具备授权与 inference，不用认证成功代替。

共享凭据迁移不完成时，允许进行 fake/隔离测试凭据端口实验，但不得宣称产品已共享登录，也不得复制旧密文作为正式路径。

## 4. G2：首条真实执行闭环

目的：从目标到验收产物，形成可暂停和恢复的单机协作运行。

工作：接一条获准真实模型 route，选取读取/写独立产物等工具；实现顺序邮箱、Activity、预算原子预留、确定性 Gate、工具资源仲裁、checkpoint、在途效果核对；支持用户输入和交接。

完成信号：真实目标完成分叉、调用工具、合流与验收；模型流中断、预算不足和重启不重复效果；接近软限额可收尾；未知效果进入核对；无秘密进入公开日志、事件与 renderer。

验证范围覆盖真实费用/usage 可见性和 provider 特性，离线 fixture 不代替真实账号验收。具体真实供应商与测试样本在 G1 完成后选择。

## 5. G3：工作台与基本知识管理

目的：用户从图观察和控制工作，而非依赖后台日志。

工作：确定 UI/宿主/图布局方案，建立独立应用服务、GoalSnapshot 与流投影；实现首页、图详情、待处理输入/审批、模板与员工、模型与预算页；接入 MemoryStore 的目录树、查看编辑、关键词/分类/时间搜索和自动长期上下文。

完成信号：用户能暂停、修改、加派、交接和插入拦截 binding，看到命令实际生效；后台/多面板/重连不丢正文与终态；目录和记忆修订可管理，超长注入有解释，权限隔离成立。

工程选型必须用实际布局与订阅原型验证。不得把 PolyQuota 的 Vue/Electron 目录、IPC 名称和数据库当作 GraphAgent 默认方案。

## 6. G4：Recap、做梦与技能闭环

目的：让短任务经验和长期整理可控、可检查、可回滚。

工作：任务结算触发 recap；技能草稿与版本管理；支持手动/空闲/定时做梦，从用途分组的批量模型候选选择 dreamModel，允许与工作模型相同；独立上下文、候选/反思/提交阶段、sourceRefs 验证、CAS、journal 与冲突界面；全程预算与通知规则。

完成信号：短任务产生有证据的记忆/技能；做梦可使用相同模型但保持独立上下文、不扮演原员工；候选准入和证据复核有效；并发编辑不覆盖新内容；journal 不可原地改写；合并/删除不破坏运行中旧技能；整理失败不改变任务终态；无可用批量候选时按配置回退或明确排队。

这是本阶段产品功能的一部分，不因首页宣传互动排除而一并暂缓。

## 7. G5：扩展验证

目的：用差异场景验证契约，而非仅在单一供应商和静态任务图上成立。

工作：第二种协议/provider、语义审查员、MCP 工具、A2A 受限导入/发布、远端异步结果与取消核对；验证长期实例 page-out/激活、反亲和与更大图布局。可执行第三方插件、跨 Goal 实时共享工作、分布式 Worker 和高级绩效调度仍需专项设计。

完成信号：新增能力不修改通用控制面基础类型；跨模型交接保留效果事实、隔离原生状态；外包费用与权限受约束；远端取消/结果未知能解释；协议互操作有固定版本 fixture。

## 8. 验证层次

| 层次            | 主要证据                                                                           |
| --------------- | ---------------------------------------------------------------------------------- |
| 领域契约        | 图修改原子性、版本、生命周期、共享取消、循环与权限不变量                           |
| 运行恢复        | 关键提交点注入崩溃、重放、重复投递、旧 epoch、未知工具效果                         |
| 预算与策略      | 并发预留、用量未知/迟到、软限额收尾、辅助任务费用、安全失败                        |
| Provider/工具   | 无网络 fixture、完整工具配对、原生状态、取消与最小真实账号闭环                     |
| Agent Loop/提示 | turn 与任务终态分离、输入边界、截断/中断工具参数、用途能力、来源权威、实际调用快照 |
| 知识整理        | 树目录检索、revision 冲突、独立上下文、journal 不变性、技能版本保护                |
| UI/宿主         | fake 应用服务、图干预、多面板/断线、生命周期、真实宿主资源与打包行为               |

实现修改按仓库要求运行 format、typecheck、test、build；涉及 Electron/native/打包再运行 package。纯文档修改只检查文档格式、链接与设计一致性，不执行代码检查、测试或编译；这些验证不能证明上述运行完成信号。

## 9. 工程启动前需落实的决策

- 领域 schema 与状态表定稿，优先解决 Task/Assignment 的恢复和取消语义。
- Ledger/内容存储选择，以原子预算、outbox 与恢复实验为依据。
- 本机 Activity 与工具进程协议，明确子进程取消和效果核对能力。
- 共享凭据代理的宿主、传输与跨产品迁移验证。
- 首个真实推理 route、usage/费用来源及跨协议 fixture。
- 实现已确定的 Markdown MemoryStore 与 SQLite 原始消息档案，验证文件发布/恢复协议；工作/辅助模型组合仍需选择。
- UI 框架、图布局和桌面/本机服务宿主，完成真实原型评估。

这些选择不阻塞本轮功能设计；实施到对应阶段时，以可审查样本和完成信号确认，不把草案当作已选定工程结构。
