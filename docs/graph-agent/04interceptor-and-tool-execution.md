## 1. 两类机制

Interceptor 可以优化输入、补充环境、修复结构化结果、精简输出、脱敏或提前给出无需继续执行的结果。Policy Gate 强制权限、信任区、数据外发和执行限制。二者经过同一调度管线，但策略等级不同：内容优化失败可以显式降级，必要安全校验失败必须阻断。

用户可以在执行图连线或节点上配置审查员；图操作生成针对消息、产物或执行边界的版本化 binding。真正拦截在运行时端口执行，不能只在 UI 或 Agent 提示词中检查。

## 2. 拦截点

| 拦截点                        | 可处理内容                     | 强制约束                                       |
| ----------------------------- | ------------------------------ | ---------------------------------------------- |
| `user-input`                  | 提炼、翻译、识别无需执行请求   | 保留原用户意图和已授权范围                     |
| `delegation-before`           | 派单说明、共享上下文、资源请求 | 不扩大权限、预算或接收者范围                   |
| `message-before-delivery`     | 跨实例或远端消息               | 验证目标及数据授权                             |
| `context-read-before / after` | 记忆、产物与文件读取           | 读取前检查访问权；读取后检查可进入上下文的内容 |
| `model-request-before`        | 完整上下文与附件               | 覆盖所有向模型外发的内容，不仅最新一句         |
| `model-response-after`        | 完整输出与结构化调用           | 未完成或未通过检查的参数不执行                 |
| `tool-call-before`            | 工具名称、参数和资源           | 变换后重新校验权限、资源与副作用               |
| `tool-result-after`           | 输出、错误、附件               | 脱敏后才进入模型、公开日志或 UI                |
| `artifact-publish-before`     | 正式交付物                     | 验证内容版本、敏感等级与发布对象               |
| `memory / skill-write-before` | 记忆修改、晋升与技能变更       | 不能写入身份规则、秘密和未授权可执行内容       |

外部 A2A、MCP、网络工具和语义审查模型的调用同样受外发边界约束。凭据注入由可信执行层处理，普通 Interceptor 看不到认证材料。

IM 适配后的群消息按实际成员/接收员工检查共享权限，复用原 messageId 与既有 Gate 收据；某接收者被阻断不宣称整条消息已对所有人交付。`@` 和全体消息只选择收件人，不提升权限。挂起、恢复和主动停止仅接受应用内的可信用户管理命令，不提供任何 Agent 控制工具或消息平台命令；普通 conversation_send 只能发送聊天，平台本人消息也不能发起管理操作。挂起仅关闭原 Loop 的推进闸门，已经运行的资源保留，临时 Loop 明确取消命令时才调用相应资源工具与效果协议。

管理自身工具命令/资源不授予停止整个作业或控制其他员工的能力；也不能通过修改图、清空会话或释放仍工作的实例间接执行仅用户可用的管理动作。空闲自动接话的工具预设只读本群消息，不提供资源或作业控制工具。

## 3. 候选契约

拦截输入 envelope 包含 `operationId`、Workspace/Goal/Attempt/Assignment、发送与接收主体、阶段、内容引用和 digest、敏感等级、权限摘要、策略 revision 与调用链。普通处理器只获得声明所需的最小视图。

| 决策            | 含义                                         |
| --------------- | -------------------------------------------- |
| `continue`      | 内容不变，继续下一阶段                       |
| `transform`     | 返回新内容引用、结构化变更说明和新 digest    |
| `block`         | 阻止当前操作，返回可公开原因与恢复建议       |
| `require-input` | 创建关联输入/审批请求，等待满足条件          |
| `short-circuit` | 返回候选终止结果，由任务验收规则决定是否完成 |

决策不能直接把 Task 改为 COMPLETED，也不能自行执行工具。需要新增工作时提交受校验的图修改建议。结果必须是符合 schema 的判别联合，超时、无效输出、冲突和能力不支持都明确记录。

每份 InterceptionDecision 固定处理器版本、输入/输出 digest、策略 revision、原因、消耗与时间。公开审计保存脱敏差异；需要保留原文时进入受控内容存储，不能把泄露字符串复制进错误说明。

## 4. 链顺序与重入

推荐管线：授权与访问前置检查 → 入口/内容变换 → 可选语义判断 → 最终内容的确定性安全检查 → schema、资源和权限复核 → 固定执行 envelope → 派发 → 输出处理与发布检查。

处理器按阶段、配置优先级和稳定 ID 顺序执行，transform 的输出成为下一处理器输入。策略快照在一次操作内固定；用户插入的新规则影响尚未派发操作。多个变换冲突时按策略拒绝或返回问题，不默默选择最后一份内容。

审批绑定最终工具、参数 digest、目标资源、权限与策略 revision。变换、参数修改、资源变化或授权过期都会使旧审批失效，必须重新判断是否仍在已授权范围内。

语义审查员通过受控审查活动运行：先执行本地脱敏与外发校验，再向获准模型提交最小资料；审查活动不再调用自身语义拦截器，但仍通过基础安全检查。调用链携带 bypass 的指定处理器 ID 和最大重入深度，不能用“我是审查员”跳过全部规则。

禁止把未审查的秘密发给云端模型询问“有没有秘密”。无法在本地确定可外发范围时阻断、采用本地审查模型或向用户请求明确输入。规则匹配与模型判断均有误判可能，界面应显示判断来源与限制。

## 5. 流式内容

请求检查覆盖长期记忆、压缩摘要、工具 schema/参数、文件与图片附件、原生状态和动态环境信息。SDK 自动附加的内容也须进入最终 envelope 或被可信执行层限制。

首版对敏感输出和需要修改的正文采用“完整消息检查后发布”，UI 可显示运行进度；不宣称已经展示的 token 可以撤回。后续增量发布必须由确定性规则声明可安全流式处理，跨块秘密匹配需要尾部缓冲。

模型 tool-call 参数只在调用完整、通过 schema 与权限校验后执行。结构修复保持 call ID 与语义，产生变换记录；不能用补猜危险参数的方式把无效调用变成可执行。

## 6. 工具目录与授权

ToolDescriptor 最小声明 `toolId`、版本、输入/输出 schema、能力、运行区域、数据分类、资源范围解析器、并发模式、取消能力、副作用、幂等/核对能力和费用来源。MCP 等接入适配器把远端声明转换为待验证目录，工具存在不代表已经授权。

有效授权为系统 ∩ Workspace ∩ 模板 ∩ Goal ∩ Assignment ∩ 当前租约。工具凭据和连接由可信端口持有，模型只看可用 schema 与脱敏结果。工作区资源以规范化 ID/路径绑定，禁止参数路径穿越、符号链接或目录变化绕开已批准范围。

工具至少分为：文件读写、终端进程、网络检索/请求、产物处理、协作控制和外部连接器。每次调用记录固定版本与真实执行目标；终端按进程及子进程管理停止，不能只关闭 stdout 读取。

记忆、技能和原始会话回溯使用[内置记忆工具](./06memory-and-self-optimization.md#81-内置工具与应用服务)，模型操作逻辑 ID/正文与版本。记忆后端文件、数据库和运行状态属于宿主管理资源，应从通用文件/终端执行区隔离，不能通过通用工具绕过记忆应用服务写入。实际隔离由工具宿主验证，不把提示词声明当作执行权限控制。

## 7. 并发与副作用

参考 DSH 的受限并发与独占屏障思想：纯读取且资源相容的工具可并行；共享写入、环境修改或明确独占工具串行。启动前重新检查模式和资源；结果按原 tool-call 顺序形成模型上下文，实际完成时间单独记录。

资源锁使用规范化读/写范围，多个锁按固定顺序取得。跨 Assignment 写同一资源时排队、拒绝或使用各自隔离目录/分支，合并形成新产物。工作区有 Git 不代表自动建立 worktree；是否隔离由任务资源策略决定。

工具执行状态区分 `planned / waiting-approval / dispatched / completed / failed / canceled-before-dispatch / unknown-effect`。未派发调用可以明确取消；已派发且无法核对的效果不能伪造“已取消成功”。重启恢复遵循[外部操作分类](./03runtime-and-scheduling.md)。

## 8. 用户授权与失败

Policy Engine 首先判断现有授权是否覆盖操作，只有缺失授权、范围扩大或明确配置要求时创建审批。审批展示具体目标、内容摘要、副作用与影响；相同已授权操作不会每轮重复询问。

必要 Gate 超时或不可用时阻断，保留待恢复操作。可选翻译/压缩器失败可按声明跳过，并显示处理未完成；不能静默退回未脱敏内容。输入过滤器只有在显式启用策略下才可短路，用户能查看原因并修改请求，不能随意把问题认定为“无意义”。

## 9. 验收与暂缓

- 秘密分别出现在输入、长期记忆、摘要、附件、工具错误与产物时，均不通过未授权外发。
- 参数变换后旧审批失效；改变目标目录不能复用原授权。
- 语义审查不会递归调用自身，也不会借 bypass 跳过本地边界检查。
- 工具执行到一半取消，已完成/未派发/未知效果分别展示。
- 两个 Assignment 同时写同一文件，形成仲裁结果且不能互相覆盖。

首版采用内置确定性处理器与受控审查员工；任意用户脚本/可执行插件、细粒度流式脱敏、远端工具强隔离和复杂 DLP 规则编辑器另做设计。拦截点与版本化证据不依赖这些扩展。
