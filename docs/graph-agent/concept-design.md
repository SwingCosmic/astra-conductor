# Graph Agent 概念设计

以下仅为整体构想，不代表具体需求或实现设计。产品功能与模块设计见[功能模块设计总览](./design.md)；阶段与优先级见[启动计划](./plan.md)。

## 整体构想

1. 该框架最特别的地方是“graph”。从一个任务入口出发，每个 Agent 都能按需派生更多 Agent，没有数量和顺序的固定限制，允许多个 Agent 同时给一个 Agent 下任务。最终得到一张执行图，绝大部分是 DAG，只有少数部分存在可控循环。
2. 每个 Agent 始终持有清晰的身份认知和特长能力卡片。派发任务像公司内同事沟通一样，允许任务外包、委托代办、分派、拒绝和排队，并根据时间和空闲情况调整排班。
3. 用户发出初始聊天后，直接看到整个任务图的执行情况，可以深入每个 Agent 的执行过程并叫停、修改或加派。
4. 可以在图执行过程的连线中增加拦截。例如敏感信息审查员可以在任何 Agent 读取或输出前修改输入输出、插入额外指令；无意义客服过滤器可以提前短路，避免浪费额度。
5. 系统提供环境上下文，包括 Goal 的总 token 或额度预算；Agent 可以据此选择模型、参数和工作强度，并在接近软限额前总结、暂停或交接。

## 主页概念

1. 侧栏与多数 Agent harness 类似，包括常用功能和会话（任务）历史。
2. 主界面上半部分是流程图，参考 CI/CD 工具，展示任务派发、分叉和执行情况，包括 Agent 实例头像、名称、当前子任务和颜色状态。正在执行的节点有动画和当前步骤指示。
3. 下半部分是俯视 2.5D 办公室场景，每个 Agent 以 Q 版形象展示工作状态，通过表情和动作区分复杂思考、普通任务和空闲。用户可以点击人物进行提醒和互动。

**范围说明**：第 1、2 项作为任务工作台设计输入；第 3 项的 2.5D 场景、人物动作表情和点击互动仅作概念宣传，不进入本阶段实现、排期或验收。

## 智能体模板

“Agent”分为两层：

- **角色模板卡片**：定义职位的能力、职责、边界和策略，参考其他框架对角色、身份和能力的设计。
- **Agent 实例**：一个模板可以创建多个“员工”，每个实例拥有不同的自我认知、上下文和记忆，但能力相同。派发时可以随机抽取、按负载选择或临时扩容，任务完成后释放临时实例。

模板可以兼容 A2A 协议中的 AgentCard；内部编排可以参考 Kubernetes 的 requests 与亲和性，并使用 Actor 模式保持员工身份和工作状态。具体边界见[01_Agent 模板与实例](./01_agent-template-and-instance.md)。

## 拦截器

拦截器用于拦截工具输入/输出、消息响应、用户输入和 subagent 派发等交互，并可以修改内容。常见作用：

1. 优化用户输入，抓住重点信息，翻译请求；
2. 拦截危险命令执行，拦截工具输出凭据泄露；
3. 提供额外环境信息便于 Agent 决策；
4. 修复结构化输出错误，精简超长工具输出。

拦截点、决策、审批和重入限制见[05_拦截器、记忆、整理与技能](./05_interception-memory-and-skills.md)。

## 记忆与自我优化

系统在空闲时具有自我记忆整理和优化能力。记忆系统不捆绑固定实现，但必须支持查看、修改、关键字检索、分类查看和时序检索；记忆内容支持类似目录树的分组管理，AI 可以自行建目录分类。

记忆在时间尺度上分级：流水记忆、短期记忆和长期记忆。长期记忆会被自动注入上下文，但优先级低于身份卡片和当前用户要求。

- **短期整理（recap）**：短任务完成后按需自动生成记忆和技能草稿。
- **长期整理（做梦）**：在系统空闲时自动、用户主动或定时触发。根据配置的 dream model 回顾一天或更长时间的记忆，与现有记忆比对后多角度整理；可以删除无用记忆、合并技能、修正短期和长期记忆、重新罗列任务清单。
- **流水记忆**：由做梦生成，一旦创建不可修改。

整理模型必须从客观角度分析内容，不得直接注入 Agent 设定和自我认知到上下文，只能作为环境参数提供。干净上下文启动比续接原 Agent 的偏差更可控。

## 模型用途分组

模型分类包含多个层级：模型家族、模型特性和用途分组。用途分组是 GraphAgent 内置的应用选择策略：

- **主模型**：必填，未配置时的兜底模型，通常就是工作模型；
- **计划模型**：`plan`/`spec` 模式和协调、产品经理角色使用，通常为次旗舰；
- **旗舰模型**：架构设计、科研探索使用，智能最高但预算消耗大；
- **工作模型**：大多数任务的主要模型，性价比更高；
- **批量模型**：大批量重复任务、临时实例和做梦使用，通常为 Flash 类模型；
- **轻量模型**：必填，用于标题生成、拦截器、文本润色等一次性辅助工作，不支持工具和 skill；
- **安全模型**：特殊，使用本地模型检查提示词注入、危险命令和凭据泄露；使用非本地模型需明确警告并确认。

用途分组只代表默认选择，实际编排可以替换；可以为用途选择多个模型，再按约束优先选择。provider、账号和模型目录属于共享 Core，本目录不重复设计。

## 会话与 Loop

除传统私聊（用户对 Agent、父 Agent 对子 Agent）外，GraphAgent 支持多 Agent 群聊，并可以直接 `@` 人或发起全体消息。任务提交后，用户或其他 Agent 可以在主会话或任意 subagent 运行中追加会话。

非暂停下追加会话有三种模式：打断（interrupt）、queue 和 steer。挂起并发起临时聊天属于更高级别的交互：暂停会停止 Agent Loop，但不会给父 Agent 发送消息，也不干扰正在运行的命令和打开的其它资源。这可以让 subagent 在获准范围内安全处理运行中的工具和资源、记录工作状态并处理临时插入事项；主动停止整个作业仍由用户执行。

`@` 消息作为 interrupt 插入，普通群消息作为 queue 通知（不含正文，类似真实 IM），Agent 可以选择查看或无视。接受任务启动时可以设置本次作业对群消息或私聊的屏蔽，一旦屏蔽则直到任务终止后才获得 queue 消息。无任务员工的普通群消息采用可配置的空闲批量接话：合并通知后轮选一个允许参与的空闲员工，决定查看/回复或无视，最多一次替补；冷却、唤醒次数和独立聊天预算限制模型用量。

具体消息路由、屏蔽、空闲接话和临时会话规则见[02_消息聊天](./02_conversation-and-messaging.md)。
