# Graph Agent 概念设计

以下仅为整体构想，不代表任何具体需求和实现设计参考

本阶段产品功能与模块设计见[功能模块设计总览](./design.md)。以下保留概念来源；其中首页 2.5D 办公室及人物互动为概念宣传内容，不属于本阶段产品功能。

## 整体构想

1. 顾名思义，该框架最特别的地方在于“graph”。从一个任务入口出发，每个agent都能按需派生更多agent，没有数量和顺序的限制，允许多个agent同时给一个agent下任务。最终得到的是一个执行图，其中绝大部分流程都是DAG图，只有少数部分会有可控的循环
2. 每个agent都始终持有清晰的身份认知和特长能力卡片。强调agent对整体任务环境的把控，派发任务时就像和公司内的同事沟通一样，允许出现任务外包，委托代办，分派，拒绝和排队等场景，并且会根据时间和空闲情况灵活调整排班
3. 用户发出初始聊天之后，看到的直接就是整个任务图的流程执行情况，可以深入观看每一个agent的执行情况并叫停，修改或者加派
4. 可以在图执行的过程的连线中增加拦截。例如增加一个敏感信息泄露审查员，任何一个agent尝试读取或者输出信息前，都可以被审查员拦截并修改输入输出，或者插入额外指令，以避免密钥和隐私信息暴露给api提供商；或者增加一个无意义客服过滤器，每当碰到用户提出无意义问题时，提前短路并终止流程，避免浪费额度
5. 系统提供足够的环境上下文，包括goal的总token或者额度预算，agent可以根据这些信息选择合适的模型，参数以及预计工作强度，并且在接近5h额度上限之类的软限制前提前总结工作并暂停或者交接

## 主页概念设计

范围说明：第 1、2 项作为任务工作台设计输入；第 3 项的 2.5D 场景、人物动作表情和点击互动仅作概念宣传，不进入本阶段实现、排期或验收。

1. 侧栏和大部分agent harness框架的设计类似，包括常用功能和会话（任务）历史
2. 主界面分为上下两块，上侧是一张流程图，参考各种cicd工具的，展示当前任务的派发分叉和执行情况，包括agent实例的头像，名称，当前子任务，颜色状态。正在执行的节点有动画效果和当前步骤简易指示
3. 下方存放一个俯视视角的2.5D办公室场景，每个agent以q版动漫大头小人的形式展现当前工作情况，头顶头像和名称标签，通过表情（包括气泡）和动作区分复杂思考任务，普通任务和摸鱼状态。用户可以点击人物形象来提醒工作和执行其他互动

## 智能体模板(AgentTemplate)

所谓的"agent"分为两层：

一层是角色模板卡片，包含了该agent能力的所有定义“职位”，可以参考其他框架对于角色、身份和能力的设计。
第二层是agent实例，一个模板可以创建多个agent实例“员工”，每个实例拥有不同的自我认知，上下文和记忆，但能力是相同的，派发agent时可以随机抽取或者增减（临时工，完成后就释放）

智能体模板可以兼容A2A协议中的AgentCard

agent编排可以参考k8s pod部署策略（requests, 亲和性等），并且使用actor模式持久化工作中状态

## 拦截器(Interceptor)

拦截器用于拦截工具输入/输出，消息响应，用户输入，subagent派发等所有消息交互，并且有一定能力修改内容。
拦截器的常见作用：

1. 优化用户输入，抓住重点信息，翻译请求
2. 拦截危险命令执行，拦截工具输出凭据泄露
3. 提供额外环境信息便于agent决策
4. 修复结构化输出的错误，精简超长工具输出

## 记忆与自我优化

在空闲时，具有自我记忆整理和优化能力。记忆系统不捆绑固定实现，但必须支持查看，修改，关键字检索，分类查看和时序检索

记忆内容必须支持类似目录树的分组管理能力，ai可以自己建目录来进行分类。

记忆系统支持时间尺度上的分级，区分流水记忆，短期记忆，以及长期记忆(openclaw的IDENTITY.md或者hermes的USER.md，优先级低于SOUL.md/agent card并且模型能自己改)。长期记忆会被自动注入上下文

### 短期记忆整理(recap)

类似hermes agent的自我反馈能力，在一个短任务完成后按需自动生成记忆和skill

### 长期记忆整理（“做梦”）

在系统空闲时自动或者用户主动触发，也可以定时触发。

根据配置的dream model（分组为批量模型）回顾一天或者更长时间的记忆内容，并且和现有记忆进行比对，进行多角度整理优化。
做梦时可以删除无用记忆，合并skill，修正短期和长期记忆，重新罗列任务清单和进行中任务总结等。
流水记忆由做梦生成，并且一旦创建就无法修改。

整理的模型必须从客观角度分析内容，不得直接注入agent设定和自我认知到上下文，只能作为环境参数提供。否则如果原agent对某件事产生了偏差，或者反复修改一份内容造成对文件全貌的认知不足，就会持续放大错误内容造成记忆整理失去作用，从干净的上下文启动会更加可控。

## 模型分类

graph agent的模型分类较为复杂，包含多个层级的分组

### 模型家族 (Family)

通常为厂商模型类别，比如GPT, Claude, Gemini, DeepSeek这样的分组。代表模型能力的训练时特征，方便根据隐含能力特征直接挑选模型

### 模型特性

常规意义上的模型/api能力特征，比如本地部署，支持格式化输出，智力强，擅长前端，擅长文档理解，视觉能力强，擅长网络安全能力，无审查，文本风格更贴近人类等

### 用途分组

用途分组是GraphAgent内置的一系列应用内用途列表

- 主模型：**必填**，在各种任务中未配置情况下兜底的模型，通常就是工作模型
- 计划模型：`plan`模式，`spec`模式下使用的模型，以及给产品经理、任务协调员等角色提供的模型。通常是次旗舰模型，综合分析能力强
- 旗舰模型：架构设计，科研探索使用的模型，具有最高的智能，当然消耗预算也很高，避免用于主要工作任务
- 工作模型：大多数任务的主要模型，也是次旗舰模型，但是性价比更高
- 批量模型：执行大批量重复任务的主要模型，主要为Flash模型。临时实例会使用这个，工作难度低，通常给出了非常明确的需求任务，可以大批量并行派发subagent执行，做梦也使用该模型
- 轻量模型：**必填**，执行会话标题等简单文本生成，拦截器运行，文本润色等轻量辅助性工作。轻量模型始终执行一次性任务，上下文环境一次性给出且不支持工具调用、skill调用等复杂agent能力。
- 安全模型：**特殊**，使用本地模型。针对提示词注入攻击、危险命令执行、凭据泄露等安全问题进行检查。如果用户不使用本地模型，需要明确给出警告并确认。

用途分组仅代表默认选择（轻量模型和安全模型的使用场景不可选择），实际编排可以更换。可以为用途分组选择多个模型，使用时根据任务的各种约束优先选择。

### AgentLoop和对话模型

除了传统私聊（用户对agent，父agent对子agent）之外，graphagent支持openclaw式的多agent群聊，并且可以直接`@`人追加会话和发起全体消息。

任务提交后，用户或者其它agent可以在主会话或任意subagent运行中追加会话。挂起并发起临时聊天、恢复和主动停止只有用户可以通过应用内管理能力执行，不通过消息平台或agent工具执行。

非暂停下追加会话有3种模式：打断，queue和steer。

暂停（挂起）并发起临时聊天属于更高级别的交互：和停止不同，暂停会停止agent loop，但不会给父agent发送任何消息，也不会干扰运行中的所有命令和打开的其它资源。这可以让subagent在获准范围内安全地处理自己正在运行的工具命令和资源，记录工作状态并处理临时插入的事项；主动停止整个作业仍由用户执行

@消息作为interrupt 模式插入，普通群消息作为queue插入通知（不含消息正文，类似真实IM应用），并且agent可以选择看或者无视。接受任务启动时允许设置本次作业对群消息或者私聊的屏蔽，一旦屏蔽则直到任务终止后才获得queue消息。如果被@时agent尚未启动，则以该消息启动新会话
无任务员工的普通群消息采用可配置的空闲批量接话：先合并通知，再轮选一个允许参与的空闲员工决定查看/回复或无视，最多一次替补；冷却、唤醒次数和独立聊天预算限制模型用量。员工普通回复不自动触发新一轮唤醒，只有新的用户发言或显式@继续讨论。
