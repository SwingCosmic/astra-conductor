## 1. 事实与策略

共享 Core 提供 provider、account、model、protocol route、模型能力、目录 revision、codec、PreparedProviderCall 和 ModelStreamEvent。GraphAgent 提供 ModelPolicy、选择策略、ModelLease、预算与失败回退，不重新定义基础模型目录。

截至本轮，服务商认证/用量目录已存在，推理骨架尚待落地。不能由 API Key、OAuth 接入或可查询配额推断某账号已有可执行 inference route。UI 的“已接入”与“可执行模型”要分别展示。

ModelPolicy 延续模板草案中的能力、上下文、质量、隐私、provider/model/protocol 允许范围和 fallback 约束。质量 tier 是策略配置及实测来源，不当作供应商名称的固定等级；隐私要求须基于可信配置/事实，不能只信模型自报。

用途分组遵循[修正后的概念设计](./concept-design.md)。记忆整理的 dreamModel 从批量用途候选中选择，允许与工作模型相同；用途分组是应用选择策略，不等于 provider 的 Batch API，也不要求模型家族不同。做梦使用独立上下文和调用租约，其费用照常归因；详细边界见[记忆设计 10.2](./06memory-and-self-optimization.md#102-做梦)。其他用途分组在模型模块专项审查时继续细化，本轮不展开。

空闲群聊自动接话默认从批量用途选择满足 conversation_read/tool 契约的经济模型，复用 chat profile 的受限预设：最多两个 step、每 step 默认一次真实调用，不加载技能/派单/资源工具，不另设逐消息判断模型。普通群通知仍无正文，正文由被选员工显式读取。聊天使用单独的群/Workspace BudgetAccount，回复失败、pass、替补也结算；小时唤醒上限与冷却由会话策略限制，跨线程共享预算。切换工作用途须显式配置，不自动升级旗舰，也不把支持无工具的轻量用途套进读取循环。

## 2. 选择与调用固定

调用路径：

```text
TaskRevision + TemplateRevision + Workspace 授权
  → 合并 ModelPolicy 的约束交集
  → 共享模型目录过滤能力与 route
  → 账号授权、可用性与配额事实过滤
  → 估算上下文、输出上限、时间与费用
  → 取得预算预留与账号并发槽
  → ProviderRouteSelection
  → prepareCall 固定实现代次与目录 revision
  → ModelLease 关联 Assignment 与预算
  → 最终外发拦截
  → execute(signal) 消费规范事件
```

先满足硬条件，再在可行集合内考虑成本、延迟、缓存、剩余额度与偏好。首版采用可解释的确定性排序，不让模型自由生成任意 endpoint。Agent 可以提出模型/effort/输出长度建议，策略服务核验后接受。

ModelLease 记录 leaseId、共享 selection、实现代次、目录 revision、Assignment、预算预留与有效期；不含秘密。实例结构中的 lease 是当前绑定摘要，实际调用租约由 Activity 持有，避免多个 Assignment 共用一个可变 lease。

一次流固定 provider/account/model/protocol route。目录更新、账号失效或额度变化只能影响下一次调用；已开始调用不可静默改绑。准备失败释放未消耗预留，准备与最终内容变换不一致时重新估算并校验。

## 3. 工具循环与原生状态

具体的 turn/step/call 生命周期、控制边界和工具配对见[08 Agent Loop](./08agent-loop.md)，提示编译见[10 提示词组合](./10prompt-composition.md)。本稿负责候选与租约、费用和回退，Loop 不重新实现 provider 协议。

文本、工具调用、reasoning、usage、错误和完成事件按共享契约处理。只有完整 tool-call 可以进入工具模块；工具结果保留 call ID、顺序与状态，下一轮重新构建上下文。非流响应采用同一生命周期。

response ID、reasoning/thought signature、续写标识与原生消息由匹配 codec 持有，受控持久化，公开投影脱敏。跨 provider/protocol 回退不复制不可移植状态：形成事实摘要、已验收产物与未完成清单，再开始新调用；工具调用效果仍依据账本，不能重复执行。

codec 有损转换需要明确策略与记录，若损失影响技能最低契约就拒绝候选。上下文超长先按[上下文设计](./06memory-and-self-optimization.md)剪裁/压缩，不能静默删掉未结算 tool-call 或最新用户修正。

## 4. 预算维度

| 维度                  | 表达与用途                                                  |
| --------------------- | ----------------------------------------------------------- |
| 输入/输出/缓存 token  | 分别记录 observed 与 estimated；总 token 的口径由 Goal 明确 |
| 金额                  | 金额、币种、价格来源与时间；币种不混加，未知价格不记为零    |
| 平台 credits          | 保留计量单位和转换依据，不能与金额直接相加                  |
| 时间与轮次            | 截止时间、活动时间、最大模型轮次、返工轮次                  |
| 并发与工具次数        | 执行槽、账号限额、工具/外包配额                             |
| Provider quota window | 服务商窗口、剩余事实、resetAt、获取时间和可信度             |

Goal 可以只设置其中几项上限，但派生工作的每项有效限制不得超过父级剩余授权。账号窗口是外部共享资源事实，不是用户给 Goal 的预算。其他客户端也可能消费，GraphAgent 不宣称本地预留锁住远端额度。

展示至少区分：总上限、已确认消耗、估算未确认消耗、已预留、可派发余额和整理/交接保留量。未知 token/价格保留 unknown 状态；金额硬上限下不能取得可靠上界的收费调用应排队、拒绝或由用户调整约束。

## 5. 原子预留与结算

预算分配形成 Goal → Task → Assignment 的上限树；实际消费只写 UsageEntry 一次，各层汇总同一条目。分配不是已消费，不能把父预留与子预留重复加总。

启动活动时原子创建 BudgetReservation：固定计量维度、预估上界、使用者、call/activity ID 和价格依据。可派发余额按同维度计算：上限 − 已结算消费 − 活动预留 − 未确认风险占用 − 收尾保留量。并发活动不能各自看见同一份可用余额。

结束后用 provider usage 或工具实际费用结算，释放差额。中断而未得到 usage 时保留保守估计并标记待核对；网络 abort 不表示免费。晚到真实用量以关联账目更正估计，幂等键防止重复结算。

外部服务可能超出估算、延迟报告或继续计算，硬预算代表本地拒绝新增工作的上限控制，不能保证已发出请求精确停在供应商账单上限。首版使用输入估计、最大输出与风险余量取得保守调用上界；超出仍记真实消费并停止新增派发。

取消、租约过期和重启先对账再释放。排队工作保留分配额度，活动预留到启动前才取得。语义审查、压缩、recap、做梦、失败重试和远端外包都有明确费用类别，不作为隐藏免费活动。

## 6. 软限额与收尾

系统每个安全边界提供预算快照与配额事实。临近 Goal 上限、预计下一次调用会超过窗口、或收到限流信号时进入 `finishing` 模式：禁止新分叉，降低可选工作，生成事实摘要、checkpoint 与待办，再进入配额/预算 WAITING 或交接流程；管理 PAUSED 与恢复只由用户在应用内发起。

触发规则优先依据可信剩余量、下一调用上界和 resetAt；用户提到的“5 小时窗口”由具体服务商事实表达，不内置统一 5h 计时器。事实过期时重新获取或保守排队。

Goal 应预留可配置收尾预算；若没有余额调用总结模型，则用账本与已提交产物生成机械交接清单。用户明确暂停后，窗口重置不会自动恢复；系统配额等待可按原授权在到期重新校验后恢复，并记录恢复原因。

## 7. 错误与回退

| 情况          | 首选处理                             | 不允许的处理                   |
| ------------- | ------------------------------------ | ------------------------------ |
| 认证失效      | 共享凭据服务刷新或请求重新授权       | 从 PolyQuota 数据库读 token    |
| 限流/窗口耗尽 | 等待窗口或选择获准账号，重新检查预算 | 反复即时重试耗尽窗口           |
| 传输失败      | 有上限的退避；流部分输出则新建调用   | 无限制重试、重复工具效果       |
| 模型能力不符  | 拒绝候选，重新选择                   | 悄悄取消结构化/工具要求        |
| 上下文不足    | 保留必要资料后压缩/换获准大窗口模型  | 静默截断身份、权限与未结算调用 |
| 预算不足      | 收尾、预算等待或反报价               | 自动提高用户总预算             |
| 安全阻断      | 解释阻断，要求改变内容或授权         | 换供应商逃避 Gate              |

fallback 的 `fail/degrade/queue/request-approval` 均受模板最低契约约束。degrade 只减少可选质量或可选工作，不删除必需权限和数据限制；供应商重试与 TaskAttempt 重试分别记录。

## 8. 验收与待定

- 三个并发子任务加审查活动不能超售同一余额；取消后只释放未消耗部分。
- 用量未知、中断和迟到结算不显示零消费，不重复计费。
- 配额窗口接近耗尽时先总结/保存，用户暂停不会被窗口重置取消。
- route 不支持工具/结构化输出时被过滤，目录刷新不改变在途流。
- 跨协议切换不复用 reasoning signature，旧工具效果不重做。

待定：规范 token 口径、价格端口、保守估算器、候选评分和首个真实 inference provider。共享四类协议契约与 fixture 先固定，首版真实执行可只选一条 route。
