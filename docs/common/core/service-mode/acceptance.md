# 服务模式验收矩阵与证据要求

本文配套[实施方案](./implementation-plan.md)，约束[设计计划](./plan.md)的实施验收。所有编号初始均为「未验证」；表格中的测试文件与新增命令是实施目标，不代表已有测试或已通过。

## 1. 分层与记录原则

| 层级               | 执行方式                                                   | 能证明的范围                                            |
| ------------------ | ---------------------------------------------------------- | ------------------------------------------------------- |
| L1 领域/注册测试   | Vitest，每例独立容器，替换必要依赖                         | DI、业务规则、状态机、隔离与资源归属                    |
| L2 Hono/客户端测试 | `app.request/app.fetch`、可控流与 UI 测试                  | 路由、DTO、严格校验、错误转换和客户端同步算法           |
| L3 Node 集成       | 真实 Node 进程、回环监听、临时文件和 SQLite、受控上游      | 独立运行、真实请求、回调、代理、持久化和关闭            |
| L4 Electron 集成   | 当前固定 Electron 版本、真实 renderer fetch、隔离 userData | 内部协议、session、浏览器流与取消、桌面行为和原凭据后端 |
| L5 真实账号验收    | 明确配置的真实上游与可用凭据后端                           | 对应 provider 和认证方式的实际可用性                    |
| L6 分发验收        | unpacked 与 NSIS 安装产物实跑                              | 资源、binding、启动、退出和安装/升级兼容                |

L1/L2 默认不访问真实账号。L3/L4 可用本地受控服务器验证真实传输，不因此声称完成真实供应商验收。每条记录包含提交/工作区基线、运行时版本、数据目录类别、凭据后端类别、命令或操作、预期/实际、日志或截图位置；日志不含秘密。

## 2. A 阶段：职责、装配与行为保持

建议在 `packages/core/test/` 增加服务注册/消费边界测试，在 `apps/polyquota/test/` 增加 runtime 生命周期测试；保留并迁移现有测试。

| 编号 | 层级  | 用例与通过标准                                                                                                                |
| ---- | ----- | ----------------------------------------------------------------------------------------------------------------------------- |
| A-01 | L1    | 缺失、重复、循环依赖在启动校验失败；错误能定位服务链；显式 override 成功，解析后替换被拒绝                                    |
| A-02 | L1    | 同容器同标识只构造一次；两个容器状态不共享；请求不创建新调度器/存储；测试停止后无遗留 timer                                   |
| A-03 | L1    | 构造/初始化/启动各阶段注入失败，已获得资源只释放一次且按依赖逆序；重复 stop 安全                                              |
| A-04 | L1/L3 | Node 导入 common runtime 不解析 Electron；Core/UI 继续通过现有禁止 Electron 和 reference runtime 导入的边界测试               |
| A-05 | L1    | 七家 provider 通过容器 HTTP 替换获得可控响应；自有请求服务无隐式全局 fetch 回退，无 ProviderPorts 大包转交；vendor 保留窄参数 |
| A-06 | L1    | 原 provider/配额/兑换/重置对账/批次合并/调度用例保持；调度 attach/start/stop 次数和时机明确                                   |
| A-07 | L1/L4 | 原 CredentialVault 与同连接 transaction 行为保持；保存中途失败回滚账号/凭据相关写入；缺后端只在实际读写处失败                 |
| A-08 | L1    | CLI 环境/用户目录/文件服务替换不修改全局 fetch；原 CODEX_HOME、默认路径、解析与只读语义保持                                   |

## 3. B 阶段：路由、认证与字节流

路由测试从[设计路由表](./plan.md#82-业务路由与方法映射)维护显式逐项断言，至少覆盖就绪、能力、快照、事件、账户启停/删除/刷新、全部刷新、凭据刷新、两种兑换、认证开始/完成/取消/详情、设置保存、系统状态及通知回执。

| 编号 | 层级  | 用例与通过标准                                                                                                                                                                                                           |
| ---- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| B-01 | L2    | 每个公开方法映射到指定 method/逻辑路径；操作有末尾动作；没有额外 DELETE/PATCH、通用账户 save 或未要求的详情 API                                                                                                          |
| B-02 | L2    | 路径 id 独立校验；body 重复同名 id、覆盖 id、额外字段、非法 JSON、错误 Content-Type 和非空无业务 body 被拒绝；无副作用                                                                                                   |
| B-03 | L2    | 两种兑换均走 reset-credits/redeem；aggregate 可省 type、item 必须 itemId；Settings 为完整保存且沿用现有默认值规则                                                                                                        |
| B-04 | L2    | 成功、失败、void-null 转换、schemaVersion 和 HTTP 状态映射正确；刷新业务失败 DTO 不误转成传输失败；未知异常不泄露内部信息                                                                                                |
| B-05 | L1/L2 | 两个并发认证会话的 URL/设备码/状态互不覆盖；开始结果、详情和事件使用同一 sessionId；未命中/已清理会话 404                                                                                                                |
| B-06 | L1/L2 | callback 在 finish 前到达、并发 finish、重复 finish、重复 cancel、cancel/finish 竞争、超时和保存失败均得到稳定终态；落库/轮询不重复                                                                                      |
| B-07 | L1/L2 | 只读详情不启动设备轮询；终态在配置保留期内可读，期满清理；所有终态与启动失败均释放回调/abort 资源                                                                                                                        |
| B-08 | L1/L2 | 公开快照/事件/错误/认证详情/通知不含访问或刷新令牌、API key、PKCE verifier、设备轮询秘密；授权 URL 只出现在所属会话展示 DTO                                                                                              |
| B-09 | L2    | SSE 先监听后 ready，首次无业务变化也立即收到首包；分块 UTF-8、多行 data、多帧、注释心跳均可解析                                                                                                                          |
| B-10 | L2    | 在订阅前后、快照读取中和响应回传时分别制造变更，最终快照追上最高 revision；旧快照不覆盖新状态                                                                                                                            |
| B-11 | L2    | 重连全量读取；instanceId 改变允许低 revision 新快照，旧实例迟到响应被忽略；版本不匹配明确失败                                                                                                                            |
| B-12 | L2    | 背压下缓存有界，普通状态可合并；流异常、reader cancel、AbortSignal、重复取消均清除订阅/心跳，不尝试在已开始 SSE 后写 JSON                                                                                                |
| B-13 | L2    | `/app/`、`/api/` 各只剥离一次；类似 `/api-other`、错误 host、重复前缀不误匹配；query/method/headers/body/signal 不丢失                                                                                                   |
| B-14 | L4    | 分别从原 loadFile 页面与直接加载的 Vite 页面发起非空 POST、无 body POST、GET/query；跨来源/预检与 CSP 正确；状态/headers/错误保留，JSON 不被提前消费                                                                     |
| B-15 | L4    | 真实内部协议 SSE 有首包且持续分块；abort/reader cancel/窗口销毁均释放主进程订阅；主进程调度继续且只运行一份                                                                                                              |
| B-16 | L4    | 原 loadFile/Vite 路径、默认资源引用、动态 import 和 HMR 保持；按需动态资源仅进入专用 Electron 读取服务，不经过 Hono；未知标识/路径越界/错误 MIME/非预期来源受控；未知协议路径不回退打包资源；session、CSP 与安全选项有效 |

## 4. C 阶段：独立运行与 UI 切换

Node 集成使用临时目录、明确的回环监听配置和真实 SQLite；模拟的是供应商响应或凭据后端，不是假装存在的 Node 文件/回调/HTTP 服务。回调监听测试沿用供应商参数规则，以隔离端口配置测试生命周期；实际固定端口兼容在对应真实路径验收。

| 编号 | 层级     | 用例与通过标准                                                                                                                                                                                   |
| ---- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| C-01 | L3       | 不启动 Electron 可运行 Node server；通过真实 HTTP 获取状态/能力/快照、执行设置保存并收到 SSE；默认无桌面订阅                                                                                     |
| C-02 | L3       | 真实临时 CLI 文件读取/解析遵循原路径规则且不写源文件；无凭据后端时完整导入失败，错误指向保存依赖，文件读取仍成功                                                                                 |
| C-03 | L3       | 真实 OAuth 回调监听覆盖正确/错误 path、state、超时、取消、占用端口、提前回调；Web 获得同会话展示入口；结束后端口释放                                                                             |
| C-04 | L3       | 使用本地受控上游完成真实 HTTP 请求；通过受控代理验证请求实际经过代理及 NO_PROXY 绕过；检测结果与实际应用能力区分                                                                                 |
| C-05 | L3/L4    | SQLite 保存后停止并重启仍可读；同目录第二个 runtime 被拒绝；Node 和 Electron 交替运行不覆盖 native binding，不误用产品数据目录                                                                   |
| C-06 | L3       | 无凭据后端仍可查目录/状态、读文件、监听回调、访问无需秘密的网络；需解密的刷新/兑换准确失败；不返回假的成功                                                                                       |
| C-07 | L1/L3    | timer 使用真实设置；禁用、改间隔、批次并发、停止时在途任务和异常清理符合现有调度规则                                                                                                             |
| C-08 | L2/L3/L4 | 同一 UI 门面分别使用两套 base URL/prefix；组件不分 Electron/Web 分支；无 preload 的真实 Web 路径不回退演示数据                                                                                   |
| C-09 | L2/L3/L4 | 重载按 sessionId 恢复认证展示；断线不自动取消/重开认证；显式关闭仍取消；完成/失败信息可在终态保留期内恢复                                                                                        |
| C-10 | L2/L3    | Web 通知覆盖 granted/default/denied、show/failed、无页面、超时、重复/伪造/迟到回执；只有有效 delivered 回执写去重状态                                                                            |
| C-11 | L4       | Electron 系统通知确认后写去重；页面不再重复交付；托盘、任务栏、powerMonitor/resume、窗口隐藏与单实例行为保持                                                                                     |
| C-12 | L3/L4    | 接入 stopping 后拒绝新业务；取消认证、结束流、有界排空、关闭监听/dispatcher/SQLite/数据锁；启动失败与开发重启无遗留资源                                                                          |
| C-13 | L4       | 正式 UI 所有业务调用走协议；删除旧业务 IPC 后设置→事件→快照追上→恢复设置的原 smoke 场景继续通过                                                                                                  |
| C-14 | L5       | 对声明验收的每个 provider/auth method 记录真实账号结果；Node 有可用兼容后端才声明完整持久化成功，其他配置明确标记未覆盖                                                                          |
| C-15 | L6       | unpacked 和安装后通过原 loadFile 路径启动 UI，默认资源不经过专用读取；按需动态资源读取、业务协议/CSP/模块加载正常，binding 可用，原密文可读；查询/设置/事件/退出正常；升级不改产品身份与既有数据 |

真实账号成功不是所有环境自动具备的前置。最终报告逐项列出 L5 覆盖矩阵；没有兼容 Node 凭据后端时，明确交付「真实通用能力 + 凭据依赖处不可用」，不能勾选 Node 完整导入/刷新成功。真实兑换等有副作用操作仅在已有明确授权范围内验收，否则记录未验证。

## 5. 仓库命令与最终完成标准

每个任务先运行对应模块的必要检查；阶段整合及最终提交前按仓库要求执行：

```powershell
$env:Path = "$env:NODE24_HOME;$env:Path"
pnpm format:check
pnpm typecheck
pnpm test
pnpm build
```

涉及 Electron、协议/native 或打包时执行 `pnpm package`，并补 L4/L6 实际运行证据。计划新增的 `test:protocol`、`test:server` 在脚本真正落地后纳入检查；现有 `test:ipc` 在过渡期继续有效，正式清理时迁移其断言和命令说明。

最终完成同时要求：

1. A1—C4 实施任务有对应提交/变更记录，实际路由与公开方法无漏项，服务标识/消费者/释放归属一致。
2. 四项仓库检查通过，package 与实际产物检查完成；失败项有具体输出和归因，不把基线问题写成通过。
3. L1—L4 必需用例通过，L5 按实际配置明确覆盖范围，L6 对正式桌面产物完成验证。
4. 原业务 IPC、隐式演示回退、重复实例、仅转交 fetch 的中间装配完成清理；vendor、凭据事务与非本轮产品行为保持。
5. 文档、根脚本、构建配置和运行说明反映最终代码，未实现的目标仍明确标为未实现。
