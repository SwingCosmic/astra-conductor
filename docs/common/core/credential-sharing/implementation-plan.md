## 1. 现状与落点

两款桌面产品复用 [Core 迁移服务](../../../../packages/core/src/credential-migration-service.ts)、[公共 HTTP 契约](../../contract/common-api.md)和[凭据页面](../../../../packages/shared-ui/src/credentials/CredentialsPage.vue)。每个 profile 保存独立的私有业务库、绑定与钥槽。GraphAgent Web 使用服务端已有的授权。包边界与产品接线见[项目架构](../../../architecture.md)。

## 2. 一阶段：单向建立共享

一期协议、本地安装和历史闭环分别见 [A1/A2](./broker-a1-a2-detailed-design.md)、[A3—A5](./a3-a5-export-implementation.md) 和 [A6—A8](./a6-a8-sharing-implementation.md)。

## 3. 二阶段：双向管理与版本更新

### B1 合并凭据包（已完成）

`@astra-conductor/credentials` 提供协议 SDK，`/host/windows` 提供本地安装、发现与授权连接。见 [B1 记录](./b1-credentials-package-implementation.md)。

### 双向导出与存储切换

- **B2** 两端可互换角色。导出与导入分别提交 `export-ready` 和 `import-ready`，继续使用内置存储。任一端可自行接入 broker；首次共享业务读取成功后才提交 `shared`。共享记录的新增、替换和删除受 broker 授权、修订和记录许可约束。
- **B3** 准备回退将获准快照加密写入内置库并回读，提交 `private-ready`。用户随后切换，内置业务验证与 `private` 提交成功后才清理旧代次的密钥与授权。重入使用当前迁移密钥，读取共享最新修订。
- 用户已完成本机两个开发 profile 的转换，并确认 PolyQuota 和 GraphAgent 均可正常刷新和获取数据。操作恢复及故障验收见[本端状态机](./state-machine.md)。普通 Key、多协议路由和模型目录编辑页面的交付范围见[供应商实施方案](../provider/implementation-plan.md)。

### B4 独立发布与生产下载

B3 的双向共享实测通过后，将该次验收使用的独立 broker 自包含产物发布到 GitHub Releases。提供版本、平台、兼容清单、摘要及发行签名。核对线上资产与已验产物后，给两款产品配置真实下载源和版本选择，接通下载进度、校验与失败重试，并复用 A3 安装/重装入口。

使用实际 Release 分别在两端验证首次下载、校验、安装、共享接入和重装。覆盖平台、协议或 API level 不兼容、签名或摘要错误、解包路径约束、并发安装及下载中断后保留旧安装。生产分发记录包含 Release 标识、资产摘要和两端结果。后续 B5/B6 如需新的 broker 能力，按实际协议与 API 变更发布对应版本。

### 元数据升级触发重新导出

**B5。** 现有初始化只允许发布第一个版本。实施需要在独立 broker 增加候选版本构建、维护屏障、版本发布与回执查询能力，由 SDK 和两个宿主接入。若增加必需 RPC，相应提高所需 API level，在开启升级前核实已安装及运行组件的能力。[凭据共享设计第 6 节](./design.md#6-数据版本与一致性)

1. **识别升级。** 为产品管理的导出元数据定义格式版本，在受完整性保护的版本信息中记载。已发布旧库缺少该标记时，按其已知旧格式读取。两端打开同一库均能识别“需要重新导出”及目标格式。只有获准处理完整版本的一端才能发起。普通单条记录修改或 token 刷新只增加记录修订。
2. **构建候选。** 以当前权威版本 N 及其已提交修订水位为源。应用侧用 Core 提供的元数据转换器更新已识别记录，broker 负责通用存储与许可。候选 N+1 保留 vault 身份、记录 ID、归属、修订连续性、未知扩展/不透明记录、幂等回执索引和事件水位。版本复制或重加密保留记录已有的创建者与最近更新者。已删除记录不得复活。N+1 表示后继版本，实际使用独立的版本和尝试标识。旧私有快照不得覆盖共享侧更新。
3. **校验并发布。** 构建期间 N 可用。发布前短暂阻止新写入和新许可，排空或 fence 在途许可，追平并发更新。校验新记录清单、迁移包实际解密结果、必要的密钥槽及回读，再在控制库一个事务中校验基础版本、发布唯一 `currentVersion` 和回执。既有 broker 更新权不因重新导出而重置。按新版本的密钥交付规则验证在线客户端与 broker 的持久缓存，离线客户端重连后核验版本并按需重新导入。
4. **恢复与收尾。** 确认发布前失败后，可清理候选并使用新的 attemptId 和密钥重建，N 继续工作。发布响应丢失时先查原操作回执，已发布则向前恢复两端绑定。写入许可和提交绑定存储版本，旧版本未完成的提交不能写入新库。客户端只修改自己能够完整读写的记录格式。双端同时发起、重复点击、重启或已升级库再次打开，同一基础版本至多成功发布一个目标版本。旧版本在读者和恢复操作释放后回收。

### 密钥更新与版本回收

**B6。** 基于 B5 的版本协议支持独立更新迁移密钥与存储主密钥。发布前准备并验证在线客户端及服务的新密钥槽，保留旧槽供恢复。离线客户端重连后按新版本重新导入，未获准的客户端不能自动取得新密钥。版本发布后待旧读者和恢复操作释放，再回收 retired/failed 版本和关联缓存。清理失败可重试，已成功发布的版本号不复用。

### 双端验收矩阵

B2/B3 使用本地完整 broker 验证前六项的现有账号格式。多协议路由与任意具名秘密的编辑、回读和目录失效在供应商平台交付对应格式后联测。最后两项使用具备升级能力的 broker，在 B5 验收。每行使用独立产品 profile、适用于宿主的持久密钥保护与虚构凭据。桌面组合覆盖真实 safeStorage/DPAPI。另以 GraphAgent 独立 Node/Web 连接已授权的 broker，验证浏览器经 Hono API 访问共享凭据及断连、重启恢复。私有导出与私有往返使用具备内置存储的宿主。正向、反向首次建立共享分别从空 vault 开始。每次操作核对两端界面、持久绑定、实际读写后端、共享版本、修订和密钥清理状态。供应商 HTTP 使用可记录请求的受控实现。

| 场景 | 操作与通过标准 |
| --- | --- |
| 正向建立 | PolyQuota 私有导出后，在 GraphAgent 启动前独自迁移；GraphAgent 验证导入、保持内置，再独立迁移。错误密钥或取消预览无持久副作用。共享刷新在另一端可见，两端重启后使用相同 vault 与当前版本 |
| 反向建立 | GraphAgent Electron 创建私有账号并导出后退出；PolyQuota 核对预览、处理冲突、导入并先迁移。GraphAgent 重启仍为导出未迁移，随后可自行迁移。测试订阅账号和无订阅 Key，后者可管理和回读，其用量请求数为零 |
| 单端切回与重入 | 从双共享分别让 PolyQuota、GraphAgent 单独切回。退出方得到已验证私有副本并忘记自身密钥，重启仍为私有。另一端保持共享并继续提交。退出方再用迁移密钥重入，读到另一端刚提交的修订，后者无需再次准备或交接 |
| 双端切回与重入 | 依次达到两端均私有，分别修改私有副本，再以相反顺序逐一重入。错误密钥保留私有选择，正确密钥读取当前共享版本。断言两个私有改动均未自动回写；最后两端均共享且可交换修订 |
| 离线、故障与位置 | broker 离线不自动切私有。显式切回时展示已验证副本的时点与范围。无可验证快照时保持 C 并提示重连。按[回退流程](./state-machine.md#显式返回内置存储)核对切换提交前失败、提交后接线或删钥失败、远端解绑超时的状态和按钮。B3 切换失败保留原钥槽以恢复共享；A 提交后删钥失败仅续办旧绑定清理。变更已登记共享位置时核对 vault 身份与版本，两端重启后使用选定位置，选错目录不破坏原绑定 |
| 共享增删改与快照 | 一端创建无订阅 Key 或替换秘密，另一端按新修订读取。并发创建同一身份只生成一条记录。同修订并发刷新只提交一次。删除或失去访问权后切私有，快照与清单一致。无订阅 Key 可从私有快照回读，用量请求为零 |
| 从旧版 N 升级成功 | 用包含 Core 提供的旧格式夹具的真实已发布库 N，保留原始副本，每个方向在独立副本上运行。分别以两款产品为发起端打开 N，由格式差异触发重新导出。升级中让另一端刷新一条记录。校验 N+1 的用途筛选、未知字段、最新秘密、修订/事件水位，并由接收端实际解密新迁移包。两端重启及离线端重入后都能读取 N+1，再次检测无待升级项 |
| 升级中断与幂等 | 注入候选校验失败、发布响应丢失、双端同时发起、发布后客户端接线失败。失败候选不替换 N，未知结果按原回执恢复。成功时只出现一个后继版本，过时写入被拒，旧缓存清理失败可重试且不会倒退版本 |

B5/B6 另验并发重新导出与换钥、版本写入及提交边界崩溃、密钥缓存部分准备失败、版本事件丢失或重连、旧版本读者仍在线，以及发布后清理失败。新版主密钥发布后，旧版本不能降级接管。

2026-11-09 使用 broker 0.3.0（API 3，通信与存储协议 1）、PolyQuota 0.6.0 和 GraphAgent 0.2.0 完成本机验收。两个方向及同时迁移共 20 组检查通过，覆盖显式切回、离线快照、逆序重入、迁址重启和已授权 Node/Web 接入。复测入口为 `pnpm test:credential-sharing-loop --publish <完整发布目录>`。[双端用例](../../../../apps/polyquota/scripts/run-credential-sharing-loop.mjs)
