# 凭据共享恢复交付结果

2026-11-08 · 已完成。用户已确认 PolyQuota 与 GraphAgent 的共享状态正常。对应[供应商阶段一](../provider/implementation-plan.md)与[凭据共享设计](./design.md)。

## 最终行为

| 状态 | GraphAgent Electron 的行为 |
| --- | --- |
| 尚未导入 | 使用本端私有存储，可新增账号 |
| 已验证预览、`preparing` 或 `import-ready` | 私有账号保持可写；导入记录作为待接管预览展示 |
| broker 完成接管 | 排空本端在途修改后激活共享；进行中的私有授权会阻止切换 |
| 已共享绑定断连 | 保持共享已选、实际不可用，恢复后重连 |

GraphAgent Web 只经已授权 broker 访问凭据，不提供私有凭据库。共享模式当前提供读取与刷新，完整共享写入继续按 B2/B3 推进。

PolyQuota 取消导出后支持两种恢复方式：

- **恢复原导出**：broker 尚未接管且私有快照未变化时，恢复同一成功版本；已确认交付的迁移密钥不重复展示。
- **新目录重新导出**：从当前私有凭据导出到另一空目录，保留旧目录、成功版本、保护密钥与历史记录；接收方重新验证并确认新目录。

接入流程为“验证导入 → 确认导入 → 来源端启用共享”。页面分别展示已确认绑定目录、待确认预览目录、所选后端与实际后端。确认暂时失败时保留有效预览以便重试；重新验证或预览过期时清除失效预览。后台状态刷新保留编辑中的目录草稿，只有实际切换时才冻结私有操作。

恢复接口为 `POST /api/v1/credential-sharing/export/resume` 和 `/export/restart`。写操作携带实例与后端上下文；迁移密钥交付另核对当前导出版本，公开状态、事件和错误不包含凭据秘密。

## Windows 组件

独立 broker 创建受保护文件时保留既有 owner，只设置当前用户与 SYSTEM 的 FullControl DACL。用户选择目录的权限不变，支持继承 Modify 权限的目录；manifest、SQLite 主文件及 WAL/SHM 保持受限访问。

恢复流程要求组件 `0.2.0`（API `2`，协议和存储版本均为 `1`）。初始化失败的待导出操作可在原目录重试。`access-denied`、接收方未准备和预览过期均提供对应操作提示。
