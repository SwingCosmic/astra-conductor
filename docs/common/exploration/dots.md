# Codex dots 设备连接实测报告：work / pro 资源溯源

| 项目     | 内容                                                             |
| -------- | ---------------------------------------------------------------- |
| 状态     | 实测记录与官方资料核对；不是 GraphAgent 已实现能力               |
| 场景     | CDN 图片 → 目标机原始资源的跨设备定位                   |
| 设备     | 两台个人电脑（下称 work、pro）；通过远程桌面手动操作             |
| 记录日期 | 2026-11-01（UTC）；任务工作目录日期为 2026-11-02，不据此推算耗时 |

> 本报告只保留可复用的结论与证据类型。实测涉及的设备名、用户目录、具体资源目录和产物路径已移除，不作为交付物或可引用位置；需要复现时应在获准环境按同样方法重新采集。

## 1. 结论与适用范围

本次体验中，Codex dots 可以组织跨设备的分阶段工作：先在 work 提取代码和 CDN 图片清单，再由用户切换到 pro 搜索原始资源并验证。它没有展示两台个人电脑同时获准执行的能力。

“同一 dot 同一时间只能连接一台个人电脑”现已得到[官方电脑连接文档](https://learn.chatgpt.com/docs/dots/computers-and-apps)明确支持，云端电脑仍保持连接。因此不能将这个限制扩大成“整个 Codex 产品只能使用一台电脑”，也不能将云端并行 Agent 等同于多台个人电脑并行。

本次用户在目标设备的应用中手动连接，通过远程桌面在 pro 上完成点击。官方给出的设置路径也是在目标电脑打开 dot 档案、选择 Allow access。没有验证可由 Agent 自动切换，也没有验证每次切换在所有版本中都必须重复同一确认流程；远程桌面只是本次操作方式，不是 dots 的产品前置依赖。

## 2. 四类证据分开记录

| 类别             | 内容                                                                         | 可以得出的结论                                     |
| ---------------- | ---------------------------------------------------------------------------- | -------------------------------------------------- |
| 官方明确规则     | 同时连接一台个人电脑，云端电脑保持连接                                       | dots 个人电脑连接有单台限制；来源见第 4 节         |
| 本次直接观察     | 两台设备都在线；最近连接的一台 `attached=true`、`is_authorized_for_tasks=true`，另一台为 false | 在线、当前附加、任务授权是不同事实，在线不代表可派单 |
| 当次工具接口描述 | 可指定非当前附加但已授权的设备；派发必须满足目标授权                         | 接口的目标寻址比当前 UI 状态更宽，不能据此推断 dots 绕过单台规则；未实际验证该组合 |
| 未验证假设       | 切换时已有进程如何继续、取消或回报；异常断线恢复；多主机 Remote 并行         | 保留为待测项，不能写成成功或失败                   |

工具字段是该会话暴露的诊断快照，不作为公开且稳定的官方 API 契约。子任务同样受目标设备授权约束，不能通过 subagent 绕过限制。

## 3. 实测过程与结论

1. 两台电脑均在线，但连接/任务授权没有同时成立；在用户切换电脑后，目标电脑变为可派发，原电脑不再显示任务授权。
2. work 上读取前端代码，提取 34 张直接引用的 CDN 图片，取得文件名、尺寸和 SHA-256。
3. 用户通过远程桌面在 pro 手动连接，随后才在 pro 派发搜索。
4. 在 pro 的资源目录内用简化名称进行候选搜索，按大小、图像信息和内容哈希核对。34 项均找到与 CDN 字节完全一致的原文件；SHA-256 一致是比视觉相似更强的内容证据，不代表逐张人工观看过图片。
5. 将定位结果反馈给同一对话。工作是串行分阶段协作；未实施两台个人电脑同时运行的实验。

原文件名通常比 CDN 名称长，包含季节、图集等前缀或 UI 语义字段，少数条目与任何命名规律都不吻合。因此候选搜索必须先按名称放宽、再以哈希确认，不能只依赖文件名相似。34/34 结果来自前序执行回报，没有在本机独立复算；清单与校验产物留在 pro 的工作目录内，未回传到 work。

对话知道文件路径，不等于另一台电脑能够读取该文件；资源扫描与匹配未修改、移动或上传原始资源。

## 4. 官方规则核对

以下均于本报告整理时核对官方页面，产品行为可能继续变化。

| 官方页面                                                                     | 本报告采用的规则                                                                                      | 不能据此推断                                                              |
| ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| [Computers and apps](https://learn.chatgpt.com/docs/dots/computers-and-apps) | 同一 dot 同时连接一台个人电脑；在该电脑的应用中授权；云端电脑保持连接                                 | 所有 Codex Remote 主机也只有一个名额                                      |
| 同上                                                                         | 保持电脑在线且应用打开；Offline 表示不可用，不等于撤销连接；dot 电脑权限与 Codex 连接、Work Sync 分开 | 曾在线就永久允许执行，或另一功能的连接自动授予 dot 权限                   |
| [Tasks and memory](https://learn.chatgpt.com/docs/dots/tasks-and-memory)     | 已有任务保留原始电脑或云端环境；切换 dot 选中电脑不迁移任务；可使用事先配置的 Codex 云端编码环境      | 切换后任务文件、浏览器会话或正在运行的命令自动搬到新电脑                  |
| [Remote connections](https://learn.chatgpt.com/docs/remote-connections)      | Codex Remote 是独立的主机访问工作流，可逐主机配对并切换主机                                           | Remote 的多主机配对证明 dots 能同时派发到多台个人电脑，或已证明多设备并行 |

因此使用“OpenAI dots 设备连接”描述本次体验更准确；它可以发起 Work/Codex 任务，但 dots、Codex Remote、Work Sync 不能合并成同一种授权或迁移机制。

## 5. 使用体验与限制

| 维度         | 收益                                             | 本次暴露的成本或限制                              |
| ------------ | ------------------------------------------------ | ------------------------------------------------- |
| 数据就地处理 | 大量资源留在 pro，仅回传清单、证据和少量结果 | 对话知道文件路径，不代表另一台电脑能够读取文件    |
| 连续协作     | 同一目标可串联两种本地环境，保留解释和任务结果   | 每个阶段需明确执行设备与输入，切换不迁移原任务    |
| 可用性判断   | 设备列表能区分在线和任务授权                     | 只看在线容易误派；等待点击连接成为关键路径        |
| 人工控制     | 用户明确决定哪个个人电脑可用于 dot 任务          | 本次需要远程桌面接触目标电脑，不能无人在场地切换  |
| 并行         | 云端与背景工作可独立组织                         | 不应承诺 work/pro 个人电脑并行；本次没有并行证据  |
| 交付         | 内容哈希能跨阶段核实同一资源                     | 仅保存远端路径不构成交付到 work；缺少显式传输清单 |

GraphAgent 应吸收“位置、授权、能力和产物归属必须显式”的经验，同时以自主 Worker 协议设计多设备容量；不能把 dots 的 UI 切换方式当成 GraphAgent 的执行架构，也不能承诺替第三方系统突破授权限制。

## 6. 待验证事项

- 在获准的测试范围内，分别观察“已有任务正在运行时切换”“单纯离线”“明确撤权”三种情况，记录效果和回报；不把任务不迁移理解为必然继续或必然终止。
- 核对切换后的旧任务跟进条件、错误原因及恢复入口，记录应用版本和执行环境。
- 独立测试 Codex Remote 的多主机访问和并行能力；不复用 dots 的测试结论。
- 对产物做显式传输实验：源设备、目标设备、内容哈希、授权和回执均齐全后，才能声称交付到本机。
- 未来工具若出现“已授权但未 attached”目标，先核对对应产品路径，再测试寻址，不根据接口描述推断当前 dots 已放宽限制。
